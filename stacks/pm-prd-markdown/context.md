# Project Context: PM PRD Markdown

## Architecture Shape
PRD Workspace (Problem → Goals → Epics → INVEST Stories → Acceptance Criteria)
The deliverable is a set of linted markdown files, not running code. One PRD per feature, one file per story, every story traced back to an epic and a goal.
Use for: product managers who write specs in the repo and push to Jira or GitHub Issues only after review.

## Tech Stack
- **Format**: Markdown (CommonMark + GitHub tables)
- **Linter**: markdownlint-cli2 0.18.1 (run with `npx markdownlint-cli2@0.18.1`)
- **Runtime for the linter**: Node.js 20 LTS or newer (only needed for `npx`)
- **Structure checker**: `scripts/check_prd.py`, Python 3.11+, standard library only
- **Diagrams (optional)**: Mermaid 11.x in fenced ```` ```mermaid ```` blocks, rendered by GitHub or Cursor preview
- **Push targets**: Jira (Atlassian MCP) or GitHub Issues, after `/pm-validate`

## Workspace layout
All paths are relative to the persona workspace (`workspaces/pm/`).

```
prds/                    ← one PRD per feature: prds/<feature-slug>.md
stories/                 ← one story per file: stories/<feature-slug>-<NN>-<story-slug>.md
research/                ← interview notes, data pulls, competitor notes (input, not spec)
decisions/               ← short decision records: decisions/<YYYY-MM-DD>-<slug>.md
docs/                    ← generated by commands: validation-*.md, tickets-*.md, status-*.md
glossary.md              ← one definition per domain term used in any PRD
scripts/check_prd.py     ← structure checker (copied from examples/budget-alerts/scripts/)
.markdownlint-cli2.jsonc ← lint config (copied from examples/budget-alerts/)
```

- **Entry point**: `prds/<feature-slug>.md`
- **Check command**: `npx markdownlint-cli2@0.18.1 && python3 scripts/check_prd.py .`
- **Strict check (before /pm-decompose)**: `python3 scripts/check_prd.py . --strict`

## Vibe & Style
- **Voice**: short declarative sentences. Concrete nouns. Real numbers.
- **IDs**: goals `G1`, epics `E1`, stories `<PREFIX>-01`, NFRs `NFR-PERF-1`. IDs never get reused.
- **File names**: lowercase, hyphenated, no spaces.
- **Stories**: always "As a <named user>, I want <capability> so that <outcome>."
- **AC**: always Given/When/Then, one observable outcome per Then.
- **Diagrams**: one Mermaid diagram per PRD at most. Text is the source of truth.

## Key Rules
- One PRD per file. One story per file. No story text duplicated inside the PRD, only an index row.
- Every PRD has all required headings: Problem, Goals, Non-goals, Users, Epics, User Stories, Non-functional Requirements, Edge Cases, Dependencies, Rollout Plan, Success Metrics, Open Questions.
- NFRs cover Performance, Security, Privacy, Accessibility, Internationalization and Observability. Each has a number or a named standard.
- Every story is INVEST and has at least one Given/When/Then AC.
- Traceability is explicit: story → epic → goal. A story without an epic is a defect.
- Terms used in a PRD are defined in `glossary.md`.
- `/pm-validate` runs before `/pm-decompose`. Always.
