1. What is Cursor?

Cursor is an AI-first code editor built on top of Visual Studio Code. Unlike traditional editors that bolt on AI as an extension, Cursor integrates large language models into every layer of the editing experience: completions, refactoring, search, debugging, and multi-file orchestration.

Think of it as VS Code + a senior AI pair programmer that can read your entire project, understand your conventions, and write code that matches your style.

Why Not Just VS Code + Copilot?

Capability VS Code + Copilot Cursor
AI Integration Extension (bolt-on) Native, first-class
Context Awareness Current file + neighbors Full project via Rules, Context files, and @ symbols
Multi-file Editing One file at a time Agent mode orchestrates across files
Custom Rules Not supported .cursor/rules/*.mdc enforce your standards
Slash Commands Limited built-in Custom commands in .cursor/commands/
Terminal Integration Separate AI reads errors, fixes code, reruns
VS Code Extensions Native Full compatibility (same extension ecosystem)

Under the Hood

Cursor is a fork of VS Code, so everything you know about VS Code works: extensions, keybindings, themes, settings. The AI layer sits on top, intercepting your interactions and enriching them with context.

Cursor does not replace VS Code — it is VS Code, with an AI brain grafted on. Your extensions, settings, and muscle memory all transfer.

Tab Completion

As you type, Cursor predicts your next edit and shows it as ghost text. This goes far beyond simple autocomplete — it can predict multi-line blocks, suggest the next logical edit location, and even anticipate refactoring patterns based on what you just changed.

ActionShortcutWhat Happens
Accept full suggestionTabInserts the entire ghost-text prediction
Accept one wordCtrl+→Inserts one word at a time for fine control
Reject suggestionEscDismisses the ghost text
Next edit locationTab (after accept)Jumps to the next predicted edit spot
Pro Tip

Tab predictions are context-aware. They read your open files, recent edits, and active rules. The more rules and context files you have, the more accurate and consistent predictions become.

Best for: Writing code you already know how to write, just faster. Variable names, boilerplate, repetitive patterns, completing function bodies.

Inline Edit (Cmd+K)

Select a block of code and press Cmd+K (Mac) or Ctrl+K (Windows/Linux). A small prompt appears inline where you describe the change you want. The AI edits just that region, leaving everything else untouched.

Examples:

  • “Add error handling for null input”
  • “Convert this to async/await”
  • “Add type annotations”
  • “Rename variables to be more descriptive”

Best for: Targeted refactors, adding error handling, converting patterns, or cleaning up a specific function — without leaving the editor flow.

Chat Panel (Cmd+L)

Press Cmd+L to open the Chat Panel on the right side. This is a conversational interface for asking questions, exploring code, debugging, and planning. You can reference files using @ symbols.

Examples:

  • “Explain how @app/core/database.py handles connections”
  • “Why is this test failing?” (with error pasted)
  • “What would be a good approach to add caching here?”

Best for: Understanding code, asking questions, debugging errors, planning before coding. Does not directly edit files.

Agent / Composer Mode (Cmd+I)

Press Cmd+I to open Agent Mode (also called Composer). This is the powerhouse. The AI becomes an autonomous agent that can:

  • Create, edit, and delete multiple files
  • Run terminal commands (build, test, lint)
  • Read your rules and context files automatically
  • Execute slash commands (/setup-stack, /architect, etc.)
  • Iterate on errors: if a test fails, it reads the error and fixes the code
  • Use MCP tools: query databases, call APIs, read docs

Best for: Building features, running TDD cycles, multi-file refactors, any task that requires creating or editing several files in coordination.

Agent Mode Is Where the Magic Happens

For the rest of this course, almost all work happens in Agent Mode. It is the interface that uses Rules, Commands, and Context to produce structured, professional code. Tab and Cmd+K are for quick edits; Agent Mode is for building.

3. The Context System

The quality of AI output depends entirely on the context it receives. Cursor uses @ symbols to let you attach specific context to any prompt. This is how you tell the AI what to look at.

@ Symbols Reference

SymbolWhat It AttachesExample
@file Full contents of a specific file @app/api/posts.py
@folder File tree of a directory @app/modules/
@codebase Semantic search across the entire project @codebase how is auth handled?
@web Live web search results @web FastAPI dependency injection
@docs Crawled documentation from a URL @docs https://fastapi.tiangolo.com
@git Git diff, commits, or PR context @git diff HEAD~3
@ is for Context, / is for Commands

Important distinction: The @ symbol attaches context (files, folders, search results). The / prefix invokes commands (slash commands like /setup-stack). These are different mechanisms:

@app/api/posts.py = “Read this file and include it in context”
/setup-stack = “Execute this command”

How Context Flows to the AI

When you type a message in Chat or Agent, Cursor assembles a rich context package before sending it to the LLM. Understanding this flow helps you write better prompts.

The AI sees everything at once: your rules, your project context, any files you referenced with @, and your message. This is why rules and context files are so powerful — they are injected into every prompt automatically.

Pro Tip: Context Budget

LLMs have a limited context window. Attaching too many large files with @ can dilute the AI's attention. Be selective: attach the 2-3 most relevant files, not the entire project. Use @codebase for broad searches, and @file for specific references.

4. Quick Exercise

Let’s try each of the four AI interfaces. This exercise takes about 10 minutes and will give you hands-on experience with Cursor’s AI capabilities.

Exercise: Your First AI-Assisted Edits

Prerequisites: Cursor installed, a project open (any project works).

Step 1: Tab Completion

  1. Open or create a Python file (e.g., hello.py)
  2. Start typing: def calculate_average(numbers):
  3. On the next line, start typing return
  4. Observe the ghost-text prediction
  5. Press Tab to accept

Step 2: Inline Edit (Cmd+K)

  1. Select the function you just wrote
  2. Press Cmd+K
  3. Type: “Add input validation for empty list and non-numeric values”
  4. Press Enter
  5. Review the AI’s edit and accept it

Step 3: Chat Panel

  1. Press Cmd+L to open Chat
  2. Type: “Explain the time complexity of @hello.py”
  3. Read the AI’s explanation
  4. Ask a follow-up: “How could I make it more efficient?”

Step 4: Agent Mode

  1. Press Cmd+I to open Agent/Composer
  2. Type: “Create a file test_hello.py with pytest tests for the calculate_average function in @hello.py. Include tests for: normal input, empty list, single element, and negative numbers.”
  3. Watch the Agent create the test file
  4. Observe: it reads your function, understands the validation, and writes matching tests

Checkpoint: You should now have two files: hello.py with a validated average function, and test_hello.py with 4+ tests.
