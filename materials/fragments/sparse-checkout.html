8. Sparse Worktrees for Big Monorepos

Every worktree an agent spawns is, by default, a full checkout: every service, every package, every asset in the repo gets written to disk again. On the sample monorepo that is cheap. On a real 50-package monorepo it is not — each agent pays the full checkout cost in disk and in startup time, and five parallel agents pay it five times.

worktree.sparsePaths in .claude/settings.json fixes this. When the list is present, Claude Code creates its worktrees with git sparse-checkout in cone mode: only the listed directories, plus root-level files, are written to disk. Worktrees start faster and use a fraction of the disk. In a 50-package monorepo this is the difference between seconds and minutes per agent. 

{
  "worktree": {
    "sparsePaths": [".claude", "services/payments", "contracts"]
  }
}

The Three Rules

Three rules govern how the list behaves,[3] and each one bites if you forget it:

  1. Paths are repo-root-relative. services/payments means the services/payments under the repo root — not “any directory named payments” and not a glob.
  2. All of a session’s worktrees share ONE list. There is no per-agent list. If one agent needs services/payments and another needs services/notifications, list both — every worktree in the session gets the union.
  3. Root-level FILES always come along; root-level DIRECTORIES do not. Cone mode keeps files like init.sh and .gitignore in every worktree for free, but a root-level directory only exists if it is on the list. That includes .claude itself: leave it off and worktree sessions lose their settings, deny rules, and hooks.
Pair with symlinkDirectories

Sparse paths decide what git checks out; symlinkDirectories decides which untracked directories (like .venv or node_modules) are shared into each worktree instead of being rebuilt. The sample monorepo already symlinks .venv — together the two settings keep a worktree both small and immediately runnable.

Files Outside sparsePaths Do Not Exist

A sparse worktree does not hide excluded files — they simply are not on disk. An agent asked to read services/gateway/README.md in a worktree that only lists services/payments fails, exactly as if the file had never been committed. Keep this feature observational in class: there are known path-resolution quirks in sparse worktrees, so we watch what happens rather than build labs on top of the edge cases. The sample monorepo intentionally ships without sparsePaths — Lab 7 is where you add it.

Demo 7 — Disk on a Diet

We add sparsePaths to the sample monorepo, spawn a worktree agent, and compare the worktree against the main checkout with ls and du -sh. Run this from your initialized copy of the monorepo.

  1. Add sparsePaths to the settings

    Edit .claude/settings.json so the worktree block carries the list alongside the existing keys: 

    {
  "worktree": {
    "baseRef": "head",
    "symlinkDirectories": [".venv"],
    "sparsePaths": [".claude", "services/payments", "contracts"]
  }
}

    Leave the permissions and hooks blocks untouched — only the worktree object changes.

  2. Spawn a worktree agent

    Start claude and launch a worktree-isolated agent exactly as in Section 3, with a small payments-scoped task: 

    > Spawn an agent in a worktree to add a docstring to
  services/payments — I want to inspect its checkout.

    The task itself is a pretext; we want the worktree on disk so we can measure it.

  3. Find the worktree and inspect it

    From a second terminal in the main checkout, git knows every worktree it manages: 

    git worktree list
WT=<path-of-the-agent-worktree-from-the-list>

ls -A "$WT"
git -C "$WT" sparse-checkout list

    Expected: root-level files, the three listed paths, and nothing else.

    $ ls -A "$WT"
.claude  .env  .env.example  .git  .gitignore  .worktreeinclude
CLAUDE.md  README.md  contracts  init.sh  services

$ ls -A "$WT/services"
payments          # notifications/ and gateway/ are NOT on disk

$ git -C "$WT" sparse-checkout list
.claude
contracts
services/payments

    Note what rule 3 predicted: init.sh and .gitignore came along automatically (root-level files), but specs/ did not (root-level directory, not listed).

  4. Measure the difference

    du -sh .
du -sh "$WT"

    The captured measurement:

    $ du -sh .          # main checkout, everything included
 47M    .           # (.venv 46M + .git dominate)

$ du -sh --exclude=.venv --exclude=.git .
# --exclude is GNU du; BSD/macOS du lacks it — use: du -sh -I .venv -I .git .
548K    .           # main checkout, working files only

$ du -sh "$WT"
136K    .claude/worktrees/agent-af28436fac63da09f

    The sparse worktree shares .venv (a symlink) and .git (worktree machinery), so the honest comparison is working files: 548K full vs 136K sparse — about 4× smaller on this deliberately tiny repo. Those numbers are on Diagram D9. The absolute sizes depend on your machine; the ratio is the lesson — and it grows with every package the repo adds.

Lab 7 — Scope the Checkout

Easy

Configure sparsePaths so a payments worktree checks out only what the payments work actually needs — think through which directories that is before you write the list. Spawn a worktree agent and verify the worktree contents match your prediction, directory by directory.

Hard

Deliberately OMIT .claude from your list, spawn a fresh worktree agent, and observe what breaks in the worktree session. Diagnose the failure from what you see — which settings, rules, and hooks the session is missing and why — then fix the list and show the same session behaving correctly.

You succeeded when: you can state exactly which paths a sparse worktree contains and why .claude must be listed.
