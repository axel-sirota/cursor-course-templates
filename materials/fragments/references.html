11. The Decision Framework

Everything in this course reduces to one escalation ladder. Start at the cheapest rung and climb only when the task forces you to:

  1. Scoped context (nested CLAUDE.md, sparse checkout, /context) — the cheapest tool. One session, small window, no coordination overhead. Most monorepo pain is solved right here.
  2. Subagents + worktrees — parallel implementation. Each worker gets its own context window and its own checkout, so N tasks run at once without stepping on each other. You pay N context windows, but zero worker-to-worker coordination.
  3. Agent teams — coordination. Workers share a task list and message each other. This is the most powerful rung and the most expensive one: every message and every shared-state read costs tokens on top of each worker's own window.

You saw the full subagents-vs-teams comparison in the agent-teams section; here it is again in compact form, because this is the distinction people mix up on Monday morning:

SubagentsAgent teams
CommunicationReport results to the parent onlyMessage each other directly
Shared stateNone — each has its own contextShared task list + mailboxes
Token costLower — results summarized upwardHigher — coordination traffic on top
Best forIndependent, parallelizable tasksTasks that need mid-flight negotiation

The Two Questions

Notice the tree only asks two questions: do the tasks collide on files? and do the workers need to coordinate? File collisions are an isolation problem (worktrees). Coordination is a communication problem (teams). Everything else is a plain subagent. And the leaf note applies to all three branches: scoped context via nested CLAUDE.md plus a /context check is never optional — it is the floor you stand on at every rung.
